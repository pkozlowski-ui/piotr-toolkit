Oceniasz **wyłącznie zakres treści draftu**. Nie karz tutaj za język, kształt ani wysyłkę.

PASS wymaga obu warunków:

1. Draft **niesie otwarte pytanie** o prawa do edycji widoków współdzielonych jako rzecz do
   rozstrzygnięcia — nie gubi go i nie rozstrzyga po cichu za usera.
2. Draft **nie opisuje komponentów ani design systemu** — nazwanie elementu UI w opisie, co ficzer
   robi („filtry siedzą w drawerze"), jest w porządku; naruszeniem jest pisanie o komponentach
   jako o dostarczonym artefakcie („użyto komponentu X z DS", lista komponentów, wersje DS).

FAIL, jeśli otwarte pytanie zniknęło z draftu, albo draft raportuje użyte komponenty / design
system jako treść dla zespołu.
